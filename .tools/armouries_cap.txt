## Short answer

Yes. The armory cap is not hardcoded — it is a `max_levels` **script value** evaluated in the location's scope, so it can be made to read the owner's size. Vanilla points the armory at `manpower_max_level`:

- `manpower_buildings.txt` → `max_levels = manpower_max_level`, town/city/megalopolis only
- `building_caps.txt` → `manpower_max_level = 1 + 0.025 × population` (population in thousands: 40k → 2, 120k → 4, i.e. Sevilla's vanilla cap). No rank, development or country-size term at all.

So a small nation's towns are stuck with 1–2 armory levels simply because they are small, not because of anything about the country.

Two things worth knowing before touching it:

- `manpower_max_level` is shared by **five** buildings (armory, training_fields, barracks, regimental_camp, conscription_center), so replace the *armory's* reference, not the shared value.
- Levels built above a cap are never removed (your `Location Mechanics doc` notes Sevilla's 7 armories over a cap of 4). A size-based cap therefore cannot demolish anything — it only gates new levels.

---

## How to implement it

**1. New mod-owned cap** in `abm_building_caps.txt` (same pattern as `abm_starting_manpower_max_level`):

```
abm_armory_max_level = {
	add = manpower_max_level          # vanilla 1 + 0.025 x population

	if = {
		limit = { owner ?= { num_locations <= 20 } }
		add = { desc = "abm_building_level_small_nation" value = 1 }
	}
	if = {
		limit = {
			owner ?= { num_locations <= 20 }
			development >= 20          # "tall": a developed town
		}
		add = { desc = "abm_building_level_small_tall_nation" value = 1 }
	}
	if = {
		limit = { owner ?= { num_locations <= 5 } }
		add = { desc = "abm_building_level_very_small_nation" value = 1 }
	}
}
```

**2. Point the armory at it.** Cheapest first attempt, matching your Stud Farm precedent in `abm_stud_farms.txt`:

```
INJECT:armory = {
	max_levels = abm_armory_max_level
}
```

Caveat from `memory.md`: INJECT overwriting an existing scalar in `building_types` is still unverified in game. Verify with the in-game cap tooltip (a new breakdown line must appear) and by trying to queue one more level; check `logs/error.log` for a duplicate `max_levels`. If it does not bind, the fallback is a full `REPLACE:armory` copy (the database is proven — see `abm_capital_buildings.txt` for `sergeantry`), **but** the vanilla block defines its production method inline (`unique_production_methods = { armory_maintenance = { … } }`). Inline PM names clash inside `REPLACE`, so move those five goods lines into `production_methods/` under a new name (`abm_armory_maintenance`) and reference it with `possible_production_methods = { abm_armory_maintenance }`, as the mod's other manpower buildings already do.

**3. Localization** for the two or three new `desc` keys (the breakdown line labels) — e.g. in `abm_buildings_l_english.yml`:

```
 abm_building_level_small_nation: "Small Nation"
 abm_building_level_small_tall_nation: "Small and Developed Nation"
 abm_building_level_very_small_nation: "Very Small Nation"
```

**4. Keep the sim honest.** The cap evaluator in `engine.js` only knows location values; `owner.num_locations` / `owner.total_development` would be reported as unknown and treated as 0/false, so simulations would apply no bonus. It needs a country field (location count, total development) in the scenario/`from_save.js` and an `owner` case in `trigger()`. Then update the "Building caps" paragraph of the mechanics doc.

## Defining "small" and "tall"

These are separate axes; keep them separate so neither is a proxy for the other.

**Small = how much land you own**

| Metric | Notes |
|---|---|
| `num_locations` | Own locations only. Simplest, most legible. |
| `num_locations_owned_or_owned_by_subjects_or_below` | Same but counts vassals/tributaries — **recommended in MP**, otherwise releasing vassals is a way to stay "small". Also counts colonies, which is arguably right (a colonial empire is not a small nation). |

Suggested tiers (a 10–20 location duchy is a normal minor; majors are 100+):
- ≤ 5 locations → +2
- ≤ 20 locations → +1
- above → 0

**Tall = development concentrated in your cities**

| Definition | Syntax | Trade-off |
|---|---|---|
| Location rank | `location_rank ?= location_rank:city` / `megalopolis` | Already the mod's idiom (`abm_trade_office_max_level`), but rank mostly means population (`city` needs 30k), which the cap already rewards. |
| Local development | `development >= 20` (vanilla decisions treat 18–25 as developed; Sevilla 60.5 in 1547) | Rewards the city you actually develop; the extra level is local. |
| Country average development | `owner ?= { total_development >= { value = num_locations multiply = 20 } }` | True "tall country" test (average dev/location ≥ 20); cannot be gamed by conquering low-dev land. Proven syntax: dotted country values in value blocks appear in `inheritance_contract.txt`, and block operands in triggers in your `abm_governor_triggers.txt` style. |

**Recommended rule:** bonus only when *both* hold — small by location count **and** the location itself is developed (local `development >= 20`, maybe a second step at 40). That is simple to explain ("a small nation may stack armouries in its great cities"), it is self-limiting because the extra levels compete for the same building-level budget (town 25 / city 100 / megalopolis 200 from `location_ranks/00_default.txt`), and it does not hand free manpower to a sprawling minor with 40 one-temple villages.

Avoid the mod's `country_power_score` (Minor/Major/GP in `mp_limits_values.txt`) as the "small" test: a genuinely tall minor can score as a Major through economy/manpower, which would remove the bonus exactly when it is meant to apply.

**Balance reference:** one armory level is `local_manpower = 0.01` (≈10 men/month). +2 levels in each of three towns ≈ +60 manpower/month, meaningful for a 10-location minor and negligible against a 100-location major. Also decide whether the bonus should follow the family into Age IV: `armory` is obsoleted by `barracks` (also town-only, same `manpower_max_level`), so armory-only means the rule dies when barracks unlock; extending it means replacing `barracks` too (same inline-PM caveat).

Alternative levers, for completeness: `free_building_levels` / `global_free_building_levels_modifier` raise the *total* level budget of a location, not the armory's own cap, so they would buff every building — not the right tool here. There is no country modifier for armory/manpower building levels (`hre_imperial_armory_level` is an IO-scope modifier for the HRE building only), so the script value above is the only direct route.
